Native audio models hear the raw waveform. A ceiling fan, a television in the next room, or the agent's own voice leaking out of a mobile speakerphone all arrive on the same 16 kHz PCM stream as the caller. Because no single setting fixes all three, you need to match the defense to the kind of noise on the line.

## 1. Match the fix to the noise type

| Noise type | Examples | What fixes it | What does NOT fix it |
| :--- | :--- | :--- | :--- |
| **Stationary background noise** | AC hum, fan, road rumble, keyboard clicks | Browser `noiseSuppression: true`, RNNoise (`pyrnnoise`), local Silero VAD (`min_volume=0.6`), `startOfSpeechSensitivity: LOW` | Prompt rules alone (the noise still triggers server VAD) |
| **Background human voices (crosstalk)** | TV, side conversation, nearby call-center desk | Voice-isolation DSP (Krisp VIVA `vi-tel-v2.7` / `pro-v1` or ai-coustics), `proactivity: {"proactiveAudio": true}`, prompt listening rule | Browser `noiseSuppression` or RNNoise (both treat all human voices as signal to keep) |
| **Speakerphone echo** | Agent's own voice bleeding back into the mic | Browser/carrier `echoCancellation: true`, unmuting on `turnComplete` (not `generationComplete`), prompt echo guard | Raising VAD thresholds alone |
| **Short coughs, breaths & backchannels** | Throat clear, `"haan"`, `"okay"`, `"right"` while the agent speaks | Short-backchannel recovery after `interrupted`, prompt continuation rule | Telling the model to `"stay silent and wait"` |

## 2. Layer 1: Client capture and Turn-0 mic gating

### Browser WebRTC constraints
On web and mobile WebRTC clients, turn on the hardware and browser acoustic pipeline (`echoCancellation`, `noiseSuppression`, `autoGainControl`) when opening the microphone. See [Capture, buffers & backpressure](/gemini-live/audio-engineering/#clean-the-signal-at-the-source).

### Gate the microphone during the opening greeting
When a duplex WebSocket opens before the caller speaks, streaming open-mic room tone can leak unnecessary audio prompt tokens on Turn 1 (~201 tokens measured in an earlier Live preview benchmark) or trigger a false barge-in on line click noise. Hold ambient frames during the opening greeting and open the gate as soon as the greeting finishes playing locally (`turnComplete` + local buffer drain) or when the caller genuinely barges in (`RMS > 650` for 2 consecutive 20 ms frames, keeping a 10-frame / ~200 ms rolling pre-buffer so the first syllable is preserved):

```python
# Ambient room noise with an open mic is RMS ~40 to 250.
# Human speech into the mic is RMS 1,200 to 10,000+.
# Requiring 2 consecutive 20 ms frames (>40 ms) with RMS > 650 filters single clicks and breaths.
if mic_gated:
    pre_buffer.append(pcm_chunk)  # collections.deque(maxlen=10)
    if compute_rms_int16(pcm_chunk) > 650.0:
        consecutive_speech_frames += 1
        if consecutive_speech_frames >= 2:
            mic_gated = False
            flush_local_speaker_queue()
            while pre_buffer:
                await forward_to_gemini(pre_buffer.popleft())
    else:
        consecutive_speech_frames = 0
else:
    await forward_to_gemini(pcm_chunk)
```

## 3. Layer 2: Server-side audio filters (PSTN telephony & raw WebSockets)

PSTN telephony trunks (Twilio, Plivo, SIP) and raw WebSocket clients do not run browser WebRTC processing. Run a server-side audio filter at ingress so every downstream VAD, turn detector, and Gemini Live frame receives cleaned 16 kHz PCM audio.

### Comparing server-side filter options

| Filter | Removes background voices (crosstalk)? | License & install | Sample rate & latency notes |
| :--- | :--- | :--- | :--- |
| **Krisp VIVA SDK** (`krisp_audio`) | **Yes** (`vi-tel-v2.7`, `tel-v2`, `pro-v1` isolate the primary speaker) | Commercial (`krisp_audio` wheel from `sdk.krisp.ai` + `KRISP_VIVA_API_KEY` + `.kef` model) | Accepts 8/16/24/32/44.1/48 kHz natively (raises `ValueError` on other rates). Adds ~20 ms latency. Use `vi-tel-v2.7.kef` for 16 kHz telephony or `pro-v1.kef` for 16 to 32 kHz close mics. Note: `ss-v1.kef` removes noise only, without voice isolation |
| **RNNoise** (`pyrnnoise`) | **No** (suppresses stationary noise only) | Open source, BSD (`pip install pyrnnoise`) | Always runs at 48 kHz (480-sample frames); resample `16 kHz <-> 48 kHz` with an anti-aliased `soxr` stream resampler |
| **Picovoice Koala** (`pvkoala`) | **No** (stationary and non-stationary noise suppression) | Commercial (`pip install pvkoala` + Picovoice `access_key`) | Input stream sample rate must match `koala.sample_rate` |
| **ai-coustics SDK** (`aic_sdk`) | **Yes** (speech enhancement and dereverberation) | Commercial (`aic_sdk` + model file or download ID) | Share read-only model weights across concurrent calls via reference counting |

<Aside type="caution" title="Operational rules for Krisp VIVA in production">
1. **Lazy-import the native module**: Import `krisp_audio` lazily inside a factory helper that returns a no-op pass-through when unconfigured so local development environments run without the proprietary wheel.
2. **Pin OpenBLAS threads**: The native Krisp library spawns an OpenBLAS thread pool by default. Set `OPENBLAS_NUM_THREADS=1` in your container.
3. **Set `OPENBLAS_CORETYPE` on AMD Zen CPUs**: OpenBLAS can issue unsupported AVX-512 instructions on AMD Zen hosts and crash the process. Export `OPENBLAS_CORETYPE=HASWELL` (Zen 1), `ZEN` (Zen 2/3), or `SKYLAKEX` (Zen 4) before loading the SDK.
4. **Silent fallback on runtime errors**: Return unfiltered PCM if an exception occurs inside the native filter session, and wait until a full 10 ms frame is buffered before emitting samples.
</Aside>

## 4. Layer 3: Local VAD, server VAD, and turn-taking models

You can run voice activity detection on your gateway/client, inside Gemini Live, or in both places at once:

| Mode | Local Silero VAD | Gemini `AutomaticActivityDetection` | When to use |
| :--- | :--- | :--- | :--- |
| **Dual local + server VAD (Recommended)** | Enabled (`confidence=0.7`, `start_secs=0.2`, `stop_secs=0.4`, `min_volume=0.6`) | Enabled (`disabled=False`) | Best for duplex voice: local Silero VAD stops speaker playback in under 50 ms on barge-in and ignores quiet room noise (`min_volume=0.6`), while Gemini's server VAD owns the turn state |
| **Server VAD only** | Disabled | Enabled (`disabled=False`) | Direct client-to-Gemini streaming when you do not run a local or gateway VAD model |
| **Custom local endpointing** | Enabled | Disabled (`disabled=True`; client sends `activityStart` / `activityEnd`) | When you want full local control over turn boundaries, or when pairing Silero VAD with a semantic end-of-turn model such as Krisp Turn Prediction (`krisp-viva-tp-v3.kef`, `threshold=0.5`) |

<Aside type="note" title="Filter before turn prediction">
When combining Krisp VIVA voice isolation with a semantic turn-prediction model (`krisp-viva-tp-v3.kef` for multi-language or `krisp-viva-tt-v2.kef` for English), run voice isolation at ingress first so turn prediction evaluates cleaned primary-speaker audio.
</Aside>

## 5. Layer 4: Gemini Live `realtimeInputConfig` settings for noisy lines

Inside `setup`, `realtimeInputConfig` and `proactivity` control how `gemini-3.8-live` reacts to noisy audio and unaddressed chatter. Note that unset sensitivity defaults differ by API surface (`START_SENSITIVITY_HIGH` on the Gemini Developer API vs. `START_SENSITIVITY_LOW` on Vertex AI), so always set them explicitly:

### 1. `automaticActivityDetection` & `proactivity`
```json
{
  "proactivity": { "proactiveAudio": true },
  "realtimeInputConfig": {
    "automaticActivityDetection": {
      "startOfSpeechSensitivity": "START_SENSITIVITY_LOW",
      "endOfSpeechSensitivity": "END_SENSITIVITY_LOW",
      "prefixPaddingMs": 200,
      "silenceDurationMs": 700
    },
    "turnCoverage": "TURN_INCLUDES_AUDIO_ACTIVITY_AND_ALL_VIDEO"
  }
}
```
- **`startOfSpeechSensitivity`**: Set to `START_SENSITIVITY_LOW` when callers are in noisy rooms, cars, or call centers so background spikes and breathing do not trigger false interruptions. Use `START_SENSITIVITY_HIGH` (with `silenceDurationMs: 500`) on clean headset or browser lines where callers give crisp one-word answers.
- **`endOfSpeechSensitivity`**: Keep at `END_SENSITIVITY_LOW` so mid-sentence pauses do not cut the caller off early.
- **`prefixPaddingMs`**: Keep at `200` to `300` ms. It sets how much speech the server must detect before committing to start-of-speech. Values around `600` ms drop 250 to 450 ms spoken letters (`"S"`, `"A"`, `"C"`) when a caller spells a name or email address.
- **`silenceDurationMs`**: Use `500` ms on clean web/headset mics, `600` to `800` ms on noisy telephony lines, and raise to `1200` ms on dictation steps where callers pause to read out phone numbers, PNR codes, or addresses.
- **`proactivity.proactiveAudio`**: Supported on `gemini-3.8-live`, `gemini-3.8-live-extended-thinking`, and legacy `2.5`; helps the model refrain from answering side remarks not directed at the agent.

### 2. `turnCoverage`
- **`TURN_INCLUDES_AUDIO_ACTIVITY_AND_ALL_VIDEO` (Default on `gemini-3.8-live` and `3.x`)**: Sends only audio segments that VAD flagged as active speech (stripping room silence between turns) alongside any video frames sent during the turn. Note: background chatter loud enough to trip VAD still counts as activity, so pair this with `START_SENSITIVITY_LOW` and a voice-isolation filter when other people are talking nearby.
- **`TURN_INCLUDES_ONLY_ACTIVITY` (Default on legacy `2.5`)**: Excludes both silent audio and video frames outside active speech windows. Set explicitly on multimodal `3.8` sessions if you only want camera frames billed while the caller is speaking.
- **`TURN_INCLUDES_ALL_INPUT`**: Sends all realtime input since the last turn, including silence and inactivity between utterances. Avoid on voice calls because continuous silence inflates `$3.00/1M` audio token billing.

## 6. Layer 5: Prompt guardrails and cough/backchannel recovery

Even with a denoiser and tuned VAD, some background speech, coughs, or narrowband telephony artifacts will reach the model. Handle those in your system instruction and turn-recovery logic:

### 1. Positive listening, language-pinning, and speakerphone echo rules
Add explicit, positively framed listening rules to your base `systemInstruction`:

```text
LISTENING AND NOISE
Reply only to the main caller. Ignore background voices, TV, traffic and other noise.
Respond only to the caller's newest utterance. If your own last sentence echoes back from a speakerphone, wait and listen for the caller.
Keep every word in the active call language regardless of background noise or caller accent, except when using English letter names and structural words ("at", "dot", "dash", "underscore") to spell email addresses or codes, or when saying untranslated proper nouns.
If a short "haan", "hmm" or a cough cuts you off, do not restart your sentence. Say only what is still needed.
```

Also pass `AudioTranscriptionConfig(language_codes=["en-IN", "hi-IN", ...])` on Vertex AI so background noise does not cause input transcripts to drift into unrelated scripts (such as Urdu or Cyrillic).

### 2. Narrowband 8 kHz consonant disambiguation
PSTN telephone lines sample at 8 kHz, which strips the high frequencies that separate `B/V`, `M/N`, `F/S`, and `P/T`. On phase cards that collect spelled names or booking codes, tell the model to ask for an anchor word (*"Was that B as in Bravo, or V as in Victor?"*) when a letter is unclear, rather than guessing.

### 3. Never write `"stay silent and wait"` for noise
Do not instruct the model to *"remain silent"* or *"produce no audio"* when it hears noise or side chatter. When a native audio model chooses not to speak, the server sends no `turnComplete` event (leaving the caller in dead air), suppresses `inputAudioTranscription` for that turn, and on `gemini-3.8-live` can leak `<no speech>` text tokens into the output transcript. Instead, handle coughs and short backchannels in your application harness.

### 4. Recover from coughs and 1-to-2-word backchannels
When a cough or a short acknowledgment (`"okay"`, `"haan"`, `"ji"`) trips server VAD during agent speech, the server emits `interrupted` and stops generating audio. Inspect the `inputTranscription` text right after `interrupted`. If it contains at most 2 words, no digits, and no stop word (`"no"`, `"stop"`, `"wait"`, `"nahi"`, `"ruko"`), send a brief user-role text turn instructing the model to continue from where it was cut off instead of waiting in silence or restarting from the beginning.
